# SpiceNest UI 改进建议

> 版本：0.1 | 日期：2026-08-28
> 定位：对当前 UI 实现（MVP v1.0.0）提出的**增强与改进建议**——不同于 PROBLEM_LOG.md（记录缺陷/规范偏差），本文档记录"设计上已有但未实现"和"可以做得更好"的点。
> 原则：建议文档，不修改任何现有代码/文档；是否采纳、何时实施由项目方决定。
> 关系：与 [ROADMAP.md](../ROADMAP.md) 第三阶段"体验优化"呼应，可作为该阶段的输入清单。

---

## 一、搜索体验（建议优先）

### S-01：「你是想说 X 吗？」纠错提示（P1）

- **现状**：SPECIFICATION 3.1 的搜索结果布局里明确画了 `.trans — （无此指令，你是想说 .tran?）` 的设计，但实现中没有。
- **建议**：搜索无结果或结果极少时，用编辑距离（Levenshtein）对候选标题做近似匹配，展示"你是想说 xxx 吗？"可点击项。
- **价值**：直接解决"输错一个字母就搜不到"的痛点，与产品"秒出结果"定位高度契合。

### S-02：搜索结果关键词高亮（P1）

- **现状**：结果卡片显示完整标题/摘要，无命中高亮；ROADMAP 第三阶段已规划"搜索结果高亮匹配关键词"。
- **建议**：卡片标题/摘要用 `NSAttributedString` 给命中的关键词片段加琥珀色背景或粗体。
- **价值**：用户一眼看到"为什么这条匹配上了"，减少翻看成本。

### S-03：首页"最近搜索"区块（P2）

- **现状**：ui-design 7.1 首页布局含"🕐 最近搜索"列表，HomeView 未实现（只有收藏区占位）。
- **建议**：用 FavoritesService（第二阶段补）的 searchHistory（最近 10 条）渲染为可点击的标签/列表，点击即重新搜索。
- **价值**：查完就走场景下，"上次查了什么"是高频需求。

### S-04：空状态推荐（P2）

- **现状**：空状态只有"未找到相关内容 / 试试其他关键词"。
- **建议**：按输入内容猜测意图，给 2-3 个推荐关键词（如输入"电容"→ 推荐"参数"类内容），或展示热门搜索。
- **价值**：空结果不再是死路，引导用户继续查。

## 二、键盘交互（建议优先）

### S-05：详情页 Cmd+D / Cmd+C / Cmd+F（P1）

- **现状**：ui-design 8.2 规定详情页"收藏 Cmd+D、复制 Cmd+C"，搜索页 Cmd+F 聚焦；均未实现（已在 PROBLEM_LOG P-010 登记为缺陷）。
- **建议**：详情页注册 Cmd+D（收藏切换）、Cmd+C（复制全部）、Cmd+F（聚焦搜索框），与全局热键共存。
- **价值**：键盘流用户（产品核心人群）的完整闭环。

### S-06：详情页代码块快速复制（P2）

- **现状**：详情页多代码块时，用户需要分别点每个代码块的复制按钮。
- **建议**：键盘 ↑↓ 在代码块间移动焦点，Enter/数字键（Cmd+1~N）直接复制第 N 个代码块。
- **价值**：与"查完就走"的键盘优先体验一致。

### S-07：Esc 分级返回的视觉反馈（P2）

- **现状**：Esc 分级返回（详情→结果→首页→关窗）已实现，但无过渡反馈，快速连按 Esc 容易"按过头"。
- **建议**：页面切换加 0.2s 淡入淡出（ui-design 8.3 已规定，见 S-12），让用户感知到"回到了哪一层"。

## 三、收藏与历史（P1）

### S-08：首页真实收藏列表（P1）

- **现状**：AppDelegate 已维护 `favorites` 数组（UserDefaults 持久化），但 HomeView 只显示"暂无收藏"占位文本，从不渲染真实收藏；收藏后回首页看不到任何变化。
- **建议**：HomeView 增加收藏卡片区（复用 ContentCardView，横向网格或列表），点击直达详情、悬停可取消收藏；AppDelegate 在 `toggleFavorite` 后刷新首页。
- **价值**：收藏功能"收了看不见"，是 MVP 目前最明显的体验缺口。

### S-09：最近查看记录（P2）

- **现状**：ROADMAP 第二阶段规划"最近查看 20 条"，未实现。
- **建议**：详情页打开时记录到 FavoritesService.recentItems，首页展示（可点击）。
- **价值**：多次对比查询（如不同电容型号参数）时快速回跳。

## 四、内容展示

### S-10：关联内容可点击跳转（P1）

- **现状**：详情页只对 command/error 渲染内容；`renderGenericDetail` 把 related 以纯文本 `• relatedId` 展示，且 command/error 详情页**完全没渲染关联内容**。
- **建议**：① 所有类型详情页底部统一渲染"相关"区；② related id 显示为中文标题并做成可点击，点击跳转对应详情页（数据里 id 均有，ContentLoader.item(withId:) 已具备查询能力）。
- **价值**：内容是网状关联的（.tran ↔ .step ↔ Time step too small），跳转打通后"查一个顺藤摸瓜"体验质变。

### S-11：代码块语法高亮（P2）

- **现状**：CopyableCodeView 纯单色文字。
- **建议**：对 .tran/.options/.model 等指令做轻量着色（指令名、参数、注释分色，可参考 ui-design 3.5 代码块配色表）。
- **价值**：仿真指令一行多个参数，着色后扫读效率明显提升。

### S-12：页面切换淡入淡出（P2）

- **现状**：`showPage` 直接切换 isHidden，无动画；ui-design 8.3 规定"页面切换 0.2s 淡入淡出"。
- **建议**：加 0.2s alpha 过渡（NSAnimationContext 或 layer 动画）。
- **价值**：符合设计规范，且配合 S-07 让层级变化可感知。

### S-13：卡片点击缩放反馈（P2）

- **现状**：卡片点击无按下反馈；ui-design 6.2 规定"点击：缩放 0.98"。
- **建议**：mouseDown 时 scale 0.98、mouseUp 恢复（0.1s）。
- **价值**：微交互符合规范，点击感更真实。

## 五、健壮性与已知坑

### S-14：滚轮滚动悬停状态 Bug 修复（P1）

- **现状**：DEVELOPMENT_PLAN 第 5/8 步明确要求"参考 KeyHub 踩坑记录：全局 mouseMoved 监听 + Timer 定期更新悬停状态（80ms，.common runloop mode），避免滚轮快速滚动时 NSTrackingArea 丢失 mouseExited 导致多个卡片同时高亮"；当前实现只有 NSTrackingArea + mouseEntered/Exited，**未做全局兜底**。
- **建议**：按 DEVELOPMENT_PLAN 方案补全局监听（卡片已提供公开的 `applyHoverState(_:)`，正是为此设计）。
- **价值**：滚轮场景是搜索结果的常态操作，高亮错乱直接影响观感。

### S-15：删除死代码 hoverView（P3）

- **现状**：ContentCardView 里 `hoverView` 创建后一直 `isHidden = true`、从不显示，是死代码。
- **建议**：删除，或真正用于悬停背景色动画。

### S-16：卡片复用避免重建（P2）

- **现状**：SearchResultView.renderResults 每次全清空 stackView 重建所有卡片，结果多时（未来 150+ 条）会有布局抖动/卡顿。
- **建议**：结果量小可暂缓；第三阶段用 NSCollectionView 或复用机制（architecture 6.4 已提及）。

## 六、可访问性与细节

### S-17：像素对齐（P2）

- **现状**：Common 里有 NXPixelUtils，但 UI 代码中未见调用（卡片 frame 位移 `+3/-3` 悬停、圆角等未做像素取整）。
- **建议**：按 CHECKLIST 3.5 对所有 frame 取整，避免非 Retina 屏字体模糊。
- **价值**：KeyHub 踩过的坑，SpiceNest 应在第二/三阶段规避。

### S-18：VoiceOver 标签补齐（P3）

- **现状**：多数图标按钮（复制、收藏、返回）有 accessibilityDescription，但卡片/列表/关联链接缺 accessibilityRole/Label（ui-design 11.3 有要求）。
- **建议**：卡片设置 `.button` role、结果列表加 label，关联链接加 label。

### S-19：热键提示键帽样式（P3）

- **现状**：首页热键提示是纯文字"按 ⌃⌥S 快速唤出"；ui-design 7.1 是键帽样式（[Ctrl]+[Alt]+[S]）。
- **建议**：做成键帽样式的小控件，首次启动更醒目。
