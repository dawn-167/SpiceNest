# SpiceNest Bug 记录归档

> 版本：0.4 | 日期：2026-08-27
> 用途：记录开发过程中发现和修复的所有 bug，便于追溯、避免同类问题复发。
> 关联文档：[QUALITY_ASSURANCE.md](QUALITY_ASSURANCE.md) 第二章「Bug 处理标准流程」

---

## 使用说明

1. **何时记录**：每个 bug 完成「第 5 步：记录归档」后，按模板追加到本文档末尾。
2. **编号规则**：Bug-001、Bug-002……按发现顺序递增，不重复、不跳号。
3. **严重程度**：
   - **阻断性**：应用无法启动、核心功能不可用 → 未清零则 CHECKLIST 结论为"不通过"
   - **影响功能**：某功能异常但有替代方案 → 未清零则 CHECKLIST 结论为"有条件通过"
   - **体验问题**：不影响功能，影响使用体验 → 可延期修复，但需记录
   - **文案错误**：文字、注释、文档错误 → 可延期修复，但需记录
4. **状态**：⬜ 待修复 / 🔧 修复中 / ✅ 已修复并验证 / ⏸ 延期处理
5. **不删除记录**：已修复的 bug 保留记录，不删除，便于后续追溯和同类问题排查。

---

## 记录模板

每个 bug 按以下格式记录，追加到本文档末尾：

```
### Bug-XXX：[简短标题]
- 发现日期：YYYY-MM-DD
- 严重程度：阻断性 / 影响功能 / 体验问题 / 文案错误
- 状态：⬜ 待修复 / 🔧 修复中 / ✅ 已修复 / ⏸ 延期
- 现象：[一句话描述 bug 现象]
- 复现步骤：1. ... 2. ... 3. ...
- 根因：[一句话说清楚为什么会这样]
- 影响范围：[列出所有受影响的场景]
- 修复方案：[改了什么，怎么改的]
- 修改文件：[文件路径 + 行号]
- 回归验证：[列出验证的场景，全部通过]
- 同类排查：[是否排查了同类问题，结果如何]
- 修复日期：YYYY-MM-DD
```
